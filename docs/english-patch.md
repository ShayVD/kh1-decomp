# The English fan patch and the port

Session 137 side thread (2026-10-27). The user owns the Japanese disc and has the community English
patch (crazycatz00's KH1 ISOMaker, "July 2025" import folder) plus an ISO it produced
("Kingdom Hearts Final Mix (English v2026-02-26)"). Nothing from either is in the repo, and nothing
may be: patch files and the patched ISO stay on the user's machine.

The matching target does not change: kh1.toml still pins the retail `SLPS_251.98`
(SHA-256 `1993a4da…`) and `kh1.elf` stays byte-identical to it. English is a port-side option only.

## What the patch changes

The ISOMaker rebuilds KINGDOM.IMG from the user's retail ISO plus an `import/` folder (465 files):

| kind | files | what the port needs |
| --- | --- | --- |
| KINGDOM.IMG data | 229 `.ard` (rooms), 226 `.evm` (events), `kanji.knj`, `sysfont.bin`, menu `.kmb` / `.bin`, worldmap and gummi `*MSG.BIN`, `btltbl.bin`, `allarea.nam`, `uitex.bin`, `atad.irx` | nothing: the port reads files through KINGDOM.IDX on whatever disc it is given |
| overlay | `wm.x` (world map) | an English variant once wm.x is decompiled natively; until then nothing |
| main ELF | `SLPS_251.98`, SHA-256 `53eca29e315f43f6cb63960f32d1737b2ea3f95e3954d6b7027f4054ca64954d`, same size (3,804,356) | see below |

The ELF inside the patched ISO is the same file as the one in the import folder (same SHA-256).
The patched ISO's KINGDOM.IDX is 53,248 bytes (retail 57,344); its directory layout otherwise matches retail.

### The ELF's data (45,744 bytes changed)

All in .data/.rodata, 0x378A48-0x4917F8. Every changed byte but one (0x4917F8) lies inside a
`PIECE` of src/data/data_*.s, i.e. bytes the port already takes from the user's ELF at build time.
No changed word is a new pointer: the 185 changed words that look like image addresses are packed
halfword pairs (glyph tables at 0x46A0E4.., layout records at 0x3E48C4..), not relocations.
So cutting the pieces from the English ELF gives the port the English strings and tables.

### The ELF's code (202 words, all in functions already in src/)

| change | where |
| --- | --- |
| glyph cell 18 -> 24 px (`li rX, 0x12` -> `0x18`), its row stride 0x120 -> 0x180 and a few `sll` counts (8 -> 6) in the same index math | text/text.c, text/wintext.c, text/wintext.nostrict_nogcse.c, text/winrow.c, hud/popup.c, hud/timer.c, screen/fade.c, menu/textfade.c, menu/choice.c |
| func_0010c720 (fldtext.c): the glyph source rectangle arithmetic rewritten (74 bytes); func_0010d470 spacing 12.0f -> 8.0f | text/fldtext.c |
| three draws (func_001f94f0, func_001f9e48, func_001fa8b0) save one more register and call a new helper the patch put in the zero padding at 0x257D10: `width = width * 4 / 3; x -= 2` | text/wintext.nostrict_nogcse.c |
| string-table pointers retargeted (`%lo` / `%hi` changes): shop, list and message-window tables now point at English tables elsewhere in the data blob (e.g. list.c's 0x3E0D20 -> 0x48BAA8) | shop/shop.c, list/list.c, msgwin/msgwin.c, text/text.c, gummi/gumisave.c, text/wintext.nostrict.c |
| a two-glyph width test 0x12 -> 0x4D | text/text.c func_001f0868, wintext func_001f9748 |

None of this is VU or compiler-specific; it is constants and a handful of rewritten lines.

## The English mode (session 137)

One build serves both discs: the disc decides.

- **Boot** (host/port/lang.c, called from kh1_cd_image_open): reads `\SLPS_251.98;1` off the
  disc image; if its SHA-256 is kh1.toml's `[english]` one, `kh1_lang_en = 1` and the patch's 214
  data runs (45,603 bytes, host/port/lang_en.h) are copied from that ELF into the data pieces.
  Any other disc (retail, the KH1_BIG.iso test builds) leaves the port Japanese. The log says
  `kh1-lang: the disc's ELF is the English patch's: English text (45603 data bytes)`.
- **lang_en.h** is generated by `tools/host/en_ranges.py RETAIL ENGLISH > host/port/lang_en.h`:
  piece name, offset, ELF file offset, length; addresses only, no bytes of either ELF. Runs stop at
  piece ends and never touch a relocation word (none changed). One changed byte is outside the
  pieces: timer.c's "/" string (compiled rodata), which the C picks (`"f"` in English).
- **Code**: include/lang.h. `KH1_EN` is 0 in the matching build (so every object is unchanged:
  kh1.elf stays byte-identical), 1 under `make KH1_EN_TARGET=1`, and `kh1_lang_en` on the port.
  `KH1_GLYPH` (18 / 24) covers most changes; `KH1_EN_AT(piece, off, ja)` the moved strings, as an
  offset into the data piece that holds the English one (always in the same src/data/*.s file
  and the same contiguous run of pieces on the port: checked on the host for every target).
- **The check**: in a copy of the repo with the English ELF as SLPS_251.98,
  `make KH1_EN_TARGET=1` builds the English side of every variant against it. Result: every
  patched function byte-identical except the ones the patch hand-wrote:
  - func_001f94f0 / func_001f9e48 / func_001fa8b0: the patch calls its helper at 0x257D10 from
    their prologues. The C does the helper's work at entry (`if (KH1_EN)`); built with
    `-DKH1_EN_NOHOOK` against the English ELF with the three prologues put back, all three match,
    so everything else in them is checked. Note func_001fa8b0's 4th and 6th arguments are the
    string and the colour, so the helper moves the string pointer back 2 bytes and scales the
    colour by 4/3 there; the C does the same, as the patched game does.
  - func_0010c720 (fldtext.c, the field glyph quad): the patch's `bnel` rewrite has no C shape.
    Read by hand: 336 glyphs a page (16 rows of 21), cells 24 x 32 (v = row * 32), the quad from
    y - 2 to y + 26 (w 20) or y + 30 (any other w).
  - func_0010d470 is unmatched: its draft (nonmatchings/session12/s12w6__0010d470_179w_tlcs.c,
    the port's copy) takes the patch's one change, the space after a code-1 glyph 12.0f -> 8.0f.
- **Checked**: kh1.elf byte-identical; `make test` PASS; the host runner on
  tests/host/fake_disc.py `--elf` (the English ELF on a fake disc) loads all 214 runs (gdb compared
  them with the ELF) and so does `make vita-armcheck`'s ARM build under qemu-arm; with the retail
  ELF or none it stays Japanese.
- **The real English ISO** (the user's "English v2026-02-26" build, its ELF the pinned one; staged
  in 380 MB parts from Downloads/kh1-test/isoparts-en, never committed): the host runner with
  tests/host/pads/dive.txt logs the `kh1-lang:` line and runs through New Game into Dive to the
  Heart as on the Japanese disc. The title's option pages ("Select vibration setting.", the
  "Difficulty / Camera / Vibration / Sound" summary, "Proceed? Yes / No"), the monologue ("So much
  to do,", "Power sleeps within you.", "If you give it form...", "Choose well.") and the pedestal
  windows ("Is this the power you seek?" with its Yes / No list, "Now, what will you give up in
  exchange?") all draw in English, spaced and wrapped as they should be.
- **Vita3K** (the same session's VPK, the English ISO as ux0:data/kh1/kh1.iso): boots to the title
  with no crash; no key reached the game there (as with earlier builds), so no text was seen.
- **Not done**: wm.x (the world map) is not native yet, and when it is, its English file (the
  patch replaces it) needs the same treatment as the ELF.
